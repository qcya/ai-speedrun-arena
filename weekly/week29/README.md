# ASTRA 跑第 29 周

本实验在 Minecraft Java 1.16.1 的独立生存存档上运行。新存档沿用 MCSR Ranked 第 29 周公开的三个维度地形种子。玩家在简单难度下自然出生，空背包出发，存档关闭作弊。原版游戏负责挖掘、移动、掉落、盔甲、饥饿、怪物行为、床爆炸和龙的死亡。官方文档见 [Weekly Race](https://wiki.mcsrranked.com/gameplay/weekly_race)，种子来自[第 29 周公开接口](https://api.mcsrranked.com/weekly-race/29)。

| 维度 | 1.16.1 地形种子 |
|---|---:|
| 主世界 | `-3400912661042936483` |
| 下界 | `-392129629567131977` |
| 末地 | `4056954346358420256` |

这期图的要塞里自然生成了可用传送门。路线在出生村取铁镐、护甲、面包和床，徒步去第二座村庄补床，再用铁镐挖进要塞。进入末地后，控制器从黑曜石平台前往中央基岩柱，等龙自行降落，再决定放床、引爆、躲避龙息或进回程传送门的时机。路线由 AI 根据本地勘察与实机试跑编写。村民、怪物、出生位置以及龙降落时机可以改变尝试结果。

## 在 Linux 上复跑

1. 建立一个 Minecraft Java **1.16.1**、Fabric Loader **0.16.14** 的客户端实例。关闭游戏，在 Prism 的实例菜单中选择「打开 Minecraft 文件夹」获得游戏目录。
2. 从仓库根目录执行下面的命令。目录参数指向含有 `mods` 和 `saves` 的那一层。脚本安装本仓库编译的客户端模组，并创建全新的独立存档。
3. 启动游戏，选择单人世界 **Weekly 29 - local seed reconstruction**，确认自定义世界生成设置，保持窗口处于游戏中。脚本从出生起执行。Esc 可以暂停。用新存档再跑一局时，设置另一个 `--world-name`。

```bash
python3 weekly/week29/prepare.py --game-dir "/path/to/instance/.minecraft"
```

`data/level.dat` 仅包含 1.16.1 的世界生成参数，初始世界没有区块和玩家数据。模组识别专用存档里的 `astra-week29.enabled` 标记，读取同目录的 `survival-route.json`。每十个有效客户端游戏刻，它把位置、背包、生命值和末地状态记入 `observed-run.jsonl`。出现原版终末之诗界面时，额外记录 `end_credits`。时间戳使用 Unix 毫秒。重新打开同一存档会开始新的观察会话，复跑用全新存档比较方便。

## 修改与构建

`data/route.json` 记录按顺序执行的动作。每个行走路标都有目标坐标和容许距离。路线还使用取箱内物资、穿装备、挖床并拾取、对准竖井向下挖等操作。游戏内衡量位置、准星、可见方块和真实背包。当计划文件变更，控制器从新文件的第一步开始。玩家所在的世界、装备和游戏时间继续由原版客户端维护。

`SurvivalRoute.java` 控制主世界步骤，`RouteMovement.java` 通过短程寻路、游戏按键和准星交互执行移动。`EndFight.java` 每刻根据末影龙的真实状态选取动作。单独的 Fabric 模组可以与基础竞技桌板共用同一个客户端。用完整 JDK 21 在仓库根目录构建：

```bash
./mod/gradlew -p weekly/week29 build
```

本地客户端使用原版随机行为。MCSR Ranked 对随机数、出生、尖柱和比赛流程有自己的处理。本次三界地形复现与官方客户端的练习场次分别标注，本地成绩只对本地实录像负责。

## 核对一局的记录

在世界关闭后，可以把存档里的日志交给审计脚本。程序校验本期出生区域、连续采样、取到铁镐和床、进入末地、龙从满血到死亡阶段，以及原版通关界面这条事件链，并给出每一段的实测时间和位置。提前中断的场次保留已经达到的里程碑，本地通关用时为空。

```bash
python3 weekly/week29/audit.py "/path/to/instance/.minecraft/saves/ASTRA-Week29/observed-run.jsonl"
```

采床动作的 `additional` 按到达该处时的实际背包计算，设为 1 即再收一张。可选补给点的 `max_ticks` 限制尝试时间，360 刻约为 18 秒。超时后继续下一个补给点。实际取得的床数由背包记录。设置 `optional: false` 会保留该处为必做步骤。只有 `count` 时按指定背包总数执行。夜间露营会先发出一次放床动作，等待世界确认床的位置，再入睡和回收。

### 第一局通关实录

实机从空背包出生到终末之诗共 **17:09.660**。15:40.909 进入末地，16:59.906 首次采样到龙生命归零。玩家带九张床进末地，使用七张后进入回程传送门。中途露营留下了两张床，路线调整了一次后续采集目标。前后使用同一个存档和角色，录像从出生连续录到通关。
