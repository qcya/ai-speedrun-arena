# 动作与计时

每个 JSON 文件是一份选手提交。CLI 与 Fabric 两侧都校验输入。keys 描述这一段实际按住的按键，ticks 描述持续游戏刻数。相邻步骤连续按住同一键会保持，发起新的点击可以插入一刻松开。移动方向按第一人称视角决定，yaw=0 面向南，pitch 正值向下，slot 选择快捷栏。攻击和使用由客户端正常处理，goal 一旦满足就提前结束本场。

| 目标 | 裁判观察 |
| --- | --- |
| displacement | 同一维度内，水平位置离开出发点达到给定距离 |
| item | 游戏背包持有指定物品达到指定件数；开场就已满足会拒绝该成绩 |
| dragon_exit | 检测到从末地出口触发的首次终末之诗界面，仅做本地实验 |

`require_target` 在该步骤执行的每一刻检查实际准星类型。方块类型匹配仅表示这次瞄中了某个方块；目标物品与必要的朝向应在方案中单独确认。可在一刻的“首次攻击”上加检查，然后持续挖掘。脚本可以从外部生成；游戏内仅读取 JSON 中列出的动作。

`python3 -m arena show ID` 保存原方案、实测起点、结果、采样坐标以及结束原因。每次有效计时从控制器开始执行到目标达成为止。刻数除以 20 是标准游戏速度下的时长；低帧率时墙钟耗时可能更久。此数字适合对照本地同条件方案，官方周榜另有计时规则。

`python3 -m arena batch` 在普通世界内要求每次手工恢复同一原始副本。内置训练场的 `tools/tournament.py` 通过独立的赛前重置请求恢复场景；模组在有人物、世界和场地标记的本地生存实例里接受这一请求。计时中输入动作无法调用命令。村民组与净场组分别计时、分别分组。

数据默认写在 `~/.ai-speedrun-arena/runs.sqlite3`。本平台面向受信任的本地参赛者；公开提交与独立裁判重算需要后续宿主隔离和验证。原始位置随时间的俯视轨迹可在桌板重播。第一人称录像直接录制游戏窗口。

## 背包与合成

在动作上设置 `"ui":"inventory"` 打开玩家背包，`"ui":"close"` 关闭容器。槽位点击写成 `"click":{"slot":36,"button":0,"action":"pickup"}`。button 0 为左键，1 为右键；action 提供 pickup 与 quick_move（Shift 点击）。这些动作要求 keys 为空，和朝向、热栏变更、准星保护分步执行。动作仅在该步骤第一刻提交，剩余刻数用于等待界面同步。槽位按当前正常容器的屏幕编号，state.screen 可核对当前界面、游标与物品。例子见 examples/craft-planks.json。
